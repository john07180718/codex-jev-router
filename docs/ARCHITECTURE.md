# 設計與責任邊界

## 兩個工作流不是同一件事

開發工作流：Codex → 按需 Skill → 本機 CLI → JEV 建議 → Codex 驗證。

GitHub CI：push / pull_request → 離線測試 → 模擬示範與基本編譯檢查。

CI 不會啟動你的 Codex、讀取私人專案或呼叫 JEV。設定 Skill 也不等於 GitHub 後台
正在替你持續運作，更不會把 JEV 變成產品執行時的依賴。

## 分層

| 層級 | 能做到 | 不能替代 |
|---|---|---|
| 全域規則 | 提醒代理按需用 Skill | 保證每個任務都正確選用 |
| Skill | 定義何時呼叫、要準備哪些證據 | 網路權限與人工資料授權 |
| Request metadata | 結構化表達目的、風險、證據是否足夠 | 證明代理填寫的敘述一定真實 |
| Python schema / policy | 拒絕不合法輸入、高風險、過大、未授權與超額請求 | 識別所有秘密與錯誤語意 |
| SQLite ledger | 同一本機狀態與 task id 的程序共同預留額度 | 防止使用者改檔或繞過工具 |
| HTTPS worker | 固定 TypeSafe 主機、不跟隨轉址、父程序超時終止 | 確定服務端未處理或未計費 |
| JEV | 固定選項、量表或 yes/no 的狹窄語意判斷 | 寫碼、多步推理、正確性證明 |
| Codex + tests | 依原始證據驗證、實作、回歸測試 | 完整無缺陷保證 |

## 呼叫前流程

先檢查 Mode / project consent / key 是否存在，再由代理決定是否值得準備片段。
`ask` 會再次檢查配置、任務有效性、資料、payload 大小、敏感模式與預算。
同一個問題不要反覆問到自己滿意；同 payload 的失敗請求也預設不重送。
只有已開啟的內部有限重試可以再送，且每一筆仍計入額度。

資料不完整時去找證據，不請模型猜；明確規則用程式，不用另一個模型判斷「要不要呼叫模型」。

## 資料最小化與 Token

`state` 只放最小足夠的證據，題目描述不要先灌輸 Codex 自己的結論。
對候選檔案，先以工具找出相關位置，JEV 可協助初篩；Codex 再讀被選中的必要原文。
第一版不提供自動全 repo 蒐集器，避免它收走不該外傳的檔案。

整個資料已先進 Codex context 後再交給 JEV，不會抹掉已消耗的 Codex token。
額外指令、工具呼叫、結果與驗證也有上下文成本。只有實測能知道淨影響。

## 任務識別與隔離

`begin` 建立 UUID task，24 小時過期；`end` 提早關閉。
正常工作與子代理須共享一個 ID。額度在 DB 交易中先預留，再送請求；
因此崩潰可能占用一次預算，但不會因回應未返回就當作免費。
日期使用 UTC，與使用者本地日界可能不同。

專案路徑與 payload 使用本機 HMAC key 產生指紋；沒有跨專案答案快取。
記錄中不包含原文，但持有 DB 的人也持有 HMAC key，不能把指紋宣稱為不可重識別匿名化。
使用者層配置記錄授權的本機路徑；不要提交配置檔。

## 預設、版本與擴充

以文檔核對的版本 `jev-1.13.0` 起步，不宣稱它永遠最新；服務不接受該版本時安全退回，
由維護者人工核對後更新。Live 回覆版本不符 pinned model 時不採納。
支援 latest/preview 名稱作為人工配置，但研究比較應固定版本並記錄實際回覆模型。

第一版只包含小型標準函式庫 CLI 與 Skill，沒有 MCP Server、網頁後台、產品交易 Gate、
跨機器分散式預算、永久答案快取、每月美元硬上限或自動讀取 Codex 私人日誌。
這些功能需要各自的安全與驗收設計，不能用一段提示詞假裝已存在。
